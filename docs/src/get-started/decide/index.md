# Decide

These pages are for the reader who has not yet decided to use Orion. Each states where Orion fits and, with the same weight, where it is the wrong tool.

- [Is Orion right for you?](./is-orion-right-for-you.md) is the one-page answer: the chart of neighbouring tools, the good-fit cases, and the cases where Orion is the wrong choice.
- [Choose a use case](./choose-a-use-case.md) routes you by what you want to build, from a REST endpoint to an AI-authored service, to the pages that build it.
- [Orion and durable execution engines](./vs-durable-execution.md) sets Orion beside Temporal, Restate and Step Functions: resume-from-failure against answer-and-forget.
- [Orion and API gateways](./vs-api-gateways.md) sets it beside Kong, Envoy and APISIX: the gateway polices traffic, Orion terminates it, and a fleet wants both.
- [Orion and automation platforms](./vs-automation-platforms.md) sets it beside n8n, Zapier and Make: an app catalogue and drag-and-drop speed against production request traffic.
- [Orion and rule engines](./vs-rule-engines.md) sets it beside Drools, OPA and GoRules: inference over accumulating facts against ordered conditions over one payload.
- [Orion and embedding dataflow-rs](./vs-dataflow-rs.md) is a build decision rather than a comparison: the engine as a library in your Rust program, or as a runtime with everything Orion adds.
