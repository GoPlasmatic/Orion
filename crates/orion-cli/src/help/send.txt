Modes:
  Sync (default)   Send data and wait for the processed result
  Async            Submit for background processing, get a trace ID back

The data payload is the business data that workflows process. For workflows
starting with a parse_json task, this is the raw JSON object.

By default the payload is wrapped in the {"data": ...} envelope for you. A
channel configured with request.body_mode = "payload" reads the whole request
body as its data, so the envelope would arrive as a single key named "data" --
pass --raw to send the payload verbatim instead. Such a channel stamps its own
metadata and accepts none from the caller, so --raw and --metadata are refused
together.

Exit codes with --wait:
  0 = trace completed, 1 = trace failed, 2 = timed out

Under --output json or yaml the trace is printed on every one of those,
including the timeout, so a caller can always parse the result.

Input Methods:
  -f <file>    Read payload from a JSON file
  -d '<json>'  Provide payload as an inline JSON string
  --stdin      Read payload from standard input

Examples:
  orion-cli send my-channel -d '{"id": "order-123", "amount": 250.00}'
  orion-cli send my-channel -f payload.json
  cat payload.json | orion-cli send my-channel --stdin
  orion-cli send my-channel -d '...' --async-mode
  orion-cli send my-channel -d '...' --async-mode --wait --timeout 30
  orion-cli send my-channel -d '...' --async-mode --wait --interval 5
  orion-cli send my-channel -d '...' --metadata '{"source": "cli-test"}'
  orion-cli send my-channel -d '...' --raw   # body_mode = "payload" channel
